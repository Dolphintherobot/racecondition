database design
sql database 
could store channels,posts,replies

channel would relate to a post
post would relate to a reply 

all posts but the primary post will
have a channelid secondary key (as I 
dont want the primary post showing up
in the join operations I do)


table channel:
primary key id,title,description, main-post-id, date


table post:
primary key id, topic,description,secondary key photo,date  

table photos (maybe,might be too big):
primary key id, varbinary photo

table reply:
primary key id,topic,description,secondary key postId, date

table button:
primary key id, integer upvotes, secondary key post id
