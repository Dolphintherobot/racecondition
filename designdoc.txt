database design
sql database 
could store channels,posts,replies

channel would relate to a post
post would relate to a reply 

all posts but the primary post will
have a channelid secondary key (as I 
dont want the primary post showing up
in the join operations I do)


table channel:
primary key id,title,description, date

table post:
primary key id, topic,description,secondary key photo,secondary key channel,date  

table photos (maybe,might be too big):
primary key id, varbinary photo

table reply:
primary key id,topic,description,secondary key postId, date

its worth noting here that the secondary key will be of that 
who created it, not neccesarly a post, it can be a reply too.
This should not matter as we can create a query to grab
all replies that have my primary key   

table button:
primary key id, integer upvotes, secondary key post id


table account:
primary key id, char NOT NULL username, char NOT NULL password, integer isAdmin,
secondary key photoId/avatar
